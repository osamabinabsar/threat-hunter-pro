# Threat Hunter Pro

Hypothesis-driven threat hunting over host and network telemetry, with ML-assisted
anomaly detection. Instead of waiting for alerts, you state a hunt hypothesis
("beaconing to one destination", "rare outbound ports, off-hours logons") and the
engine hunts your data for evidence.

**Stack:** Python, scikit-learn (Isolation Forest), stdlib CSV/JSON tooling.

## How it works

```
data/sample_netflow.csv ──▶ features.py ──▶ detect.py (Isolation Forest)
data/sample_auth.jsonl  ──▶ queries.py  (hypothesis query library)
                                └──▶ report.py (hunt-report.md + JSON findings)
```

- **Dataset** — deterministic synthetic netflow (per src/dst pair: flow counts,
  byte volume, inter-arrival regularity) and auth events with an off-hours
  beaconing implant and an unusual-port C2 channel baked in.
- **Feature extraction** — per source/destination conversation: flow count,
  total bytes, distinct dst ports, inter-arrival CV (regularity → beacon signal),
  off-hours ratio.
- **Detection** — Isolation Forest scores conversations; top-scoring outliers are
  surfaced as candidates for the analyst (this is a triage aid, not an autopilot).
- **Hunt queries** — the hypothesis library (`queries.py`) encodes classic hunts
  as reusable functions: beaconing detection, rare outbound ports, off-hours
  logons, password-spray fan-out, large rare transfers.

## Quick start

```bash
pip install -r requirements.txt
python -m hunter.cli                 # runs all hunts + ML detection, writes hunt-report.md
pytest -q                            # test suite
```

## What the demo finds

Running against the bundled synthetic data surfaces, in order of interest:

1. A **regular-interval beacon** from 10.0.4.25 to 203.0.113.66:443
   (inter-arrival CV ≈ 0.02 — machines don't talk that rhythmically; humans do).
2. **Off-hours authenticated sessions** matching the beacon host's operator.
3. An **unusual outbound port** (54321) never seen elsewhere in the dataset.

## Notes

- All data is synthetic and generated by a seeded script; no real telemetry.
- ML output is scored and ranked, never auto-blocked — the analyst decides.
- The engine consumes plain CSV/JSONL, so adapting it to Elasticsearch exports,
  Zeek logs or pandas frames is straightforward.
